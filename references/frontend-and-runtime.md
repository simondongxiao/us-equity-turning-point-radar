# GitHub HTML与单股自动分析

## 布局
桌面优先并兼容手机。中文标题“美股阶段顶底雷达”。第一屏包含数据截至、纽约/北京时间、运行状态、常态池100与有效预测数、短市场/轮动摘要（最多3条）、临时输入及机会风险榜。不放账户本金，不堆工程日志。

控制区必须同时可见：
[分析个股：代码或公司名][运行分析]
周期：[1周/5日][2周/10日][约1月/21日]
机会：[↓大到小][↑小到大]   风险：[↓大到小][↑小到大]
过滤：全部/科技成长/非科技、行业、状态、只看正优势（默认不强制）。
箭头必须是按钮，有文字/aria-label/aria-pressed；激活状态醒目。每次只选一个主排序字段，不能“机会↓后又默认按风险↑”偷改主序。列头箭头和控制区同步。用数值而不是格式化字符串排序，空值置底，稳定tie-break；保留用户选择与滚动/筛选状态。筛选不重算100股分位分数。

表格建议字段：序号、代码/公司、研究组、参考价及日期、当前阶段、机会分/净期望、风险分/ES、潜在底部价带、潜在顶部价带、修复与阶段底概率、数据可信度、关键条件。桌面固定关键列；小屏用横向滚动/卡片，不能挤成不可读小字。

个股详情以展开卡/独立页提供：
1. 结论与市场/板块不同步原因；
2. 1—3日修复与5/10/21日价带表；
3. 期限末区间、期间高低点、条件顶底形成区，说明口径；
4. K线/价带与已确认结构，历史预测用当时版本；
5. 三分支路径：上先/下先/未触达，突破确认与失败reclaim；
6. 事件/基本面证据及原文链接，硬件股保留产业链驱动，不把研究删成技术分数；
7. 尾部、失效、执行风险与单位风险计划；
8. 模型版本、样本、校准/数据缺口折叠说明。
页面上的百分比必须对应特定事件、H与参考价。榜分0—100明确是相对分，不能加%号。未校准显示“— / 未校准”，不填50%。

## 计算架构
GitHub Pages只是静态HTML/CSS/JS/JSON承载层，不能直接执行Python、桌面Codex或私密Skill。
生产推荐：Pages前端 → 已鉴权HTTPS任务网关 → 持久任务队列 → GitHub Actions/已有授权runner → 同一个Python分析入口 → 对象存储/版本化结果 → 网关回传结果 → Pages回显。

网关优先复用用户现有可用服务；没有则在新项目提供可部署实现（例如Cloudflare Worker或等价已有环境），明确真实需要的服务、授权和成本，不能凭空认为这些账户已存在。浏览器直接读公开缓存可无需鉴权；创建付费/写入任务仅对授权用户开放。

云端默认执行确定性分析脚本，不必每次唤起LLM。Skill是稳定流程说明，不是一个浏览器能直接调用的API；将其计算逻辑封装为单一analyze入口供本地Codex与云端共用。需要LLM读取事件时使用合法配置的API/runner和限额，不上传桌面登录会话、不假设本地ChatGPT订阅自动授权云端API。

## 网关协议
GET /health → gateway/runner/model/data的实际状态与版本。
生产接入必须完成用户登录/会话建立；cookie会话写请求验证CSRF，短效bearer方案验证令牌。包内模板只有请求适配层，不包含登录、鉴权网关或持久队列的实现。
POST /jobs，鉴权后接受{symbol, horizon:[5,10,21], force:false, client_request_id}。服务端解析代码，发行人身份确认；名称有歧义则返回候选供选择，不误猜。
返回202 {job_id,status,created_at}。这只表示接受任务，不代表计算或GitHub部署成功。
GET /jobs/{job_id} → queued/running/succeeded/failed/timed_out，附进度、错误类别、as_of、model_version、结果地址或JSON。鉴权并校验任务所属用户。
GET /results/{result_id} → 经过schema校验的不可变结果；公共结果只公开许可范围内的派生指标。

前端输入池内股时先打开可用缓存，同时允许更新；池外股跑完整同一模型，结果进入“临时观察”，不只过滤现有100行。结果未完成时不展示他股旧结果或假动画成功。缓存key至少含规范symbol、as_of、horizon、model/data/feature版本；事件更新需失效。单股结果可直接由网关返回，无需为每次查询重新部署整站；后续整站构建再汇总。若单股结果的prediction_snapshot_id与当前100股批次不一致，先进入临时观察，禁止混入旧批次比较榜；批量更新统一快照后再进入正式排序。

## 安全
采用服务端校验的OAuth/OIDC或等价安全用户鉴权，校验签名、iss、aud、exp、nonce/state与允许的用户身份。只依赖CORS、Referer、Origin或验证码都不是用户鉴权。长效服务凭据只保存在网关/runner秘密库；前端不得存PAT、安装令牌、API密钥或把Token写入URL/localStorage。短效用户会话采用受审计的浏览器流程，避免跨站Cookie限制造成“看似登录实则失败”。
服务端持有最小权限GitHub App安装令牌或限定仓库权限凭据，触发固定workflow，ref固定可信分支；用户输入仅做参数，不决定workflow/ref/文件路径/任意命令。ticker规范化/长度/证券主表白名单校验，防注入、SSRF和路径穿越；渲染用textContent或转义，不直插HTML。
加每用户请求限额、预算上限、并发限制、幂等、同标的同版本去重、超时和失败重试。公共网页游客默认只读；不要开放匿名任务消耗账户费用。
请求参数不拼接shell；不运行不受信任PR；不要用pull_request_target执行用户代码。锁定依赖和可信Action版本，扫描密钥。

## 自动更新
实现收盘后日常批量与每周调池的计划任务，同时保留workflow_dispatch和本地手动触发。计划先按当前授权环境启用；仅有本地手动运行时，每次运行检测周ID并自动调池，但必须说明本地不运行时不会自行更新，不能称无人值守已部署。
Cron按UTC配置，程序再按America/New_York交易所日历判断完整交易日/半日市/节假日/夏令时。避免假定“北京时间今天=美股今天”。GitHub计划任务可能延迟，页面显示真实as_of，不承诺整点推送。断电本地runner无法保证随时运行，若采用本地模式须明确标识。

## 持久化与并发
GitHub runner磁盘通常是临时的；训练台账/模型/调池版本/任务状态需持久存储。缓存不是数据库，不把cache命中当审计记录。公开Pages只包含必要可公开结果，私有状态在私有仓库的专用状态分支或受保护对象存储/数据库，按规模选择。
每个symbol结果按as_of与版本执行compare-and-swap，较旧任务后完成不得覆盖较新结果。批量/单股共享一份manifest与写锁/事务策略；单股请求不能cancel掉其他单股任务，不能因GitHub concurrency只保留一个pending而默默丢任务。由持久队列控制任务，必要时合并批处理。

发布从干净的构建目录开始，生成manifest后原子切换。不要只部署某一只单股目录覆盖全站。失败保留上一成功版本；旧数据时间明显展示。数据刷新与新闻截止不一致时分别显示。检查许可，不把需要付费许可的原始行情链/研报全文直接公开到GitHub。

## 真实部署验收
gh auth status与远端身份 → 仓库及默认分支 → 构建 → deploy → 实际Pages URL打开 → 核验当前run_id → 四向箭头排序 → 切换周期 → 池内输入 → 池外有效代码输入 → 未授权拒绝/坏代码拒绝 → 两个并发请求不会互相覆盖 → 手机浏览。
未经上述核验，不得说“HTML与临时输入已上线”。

## v1.1存储入口与兼容性
在原四向排序/周期/研究组筛选外新增可见的“存储与内存·N”按钮和细分下拉。初始四只均可见，业务标签在主表/详情显示。科技/非科技类别与研究组联动消除冲突；回到全部不会改变排序方向和周期。筛选不重算全池分数。

存储摘要来自同as_of的派生快照，显示状态、覆盖和缺口；详细跨板块/细分矩阵折叠。个股详情增加LOO同行来源与样本状态，原多周期表/技术/条件路径/基本面正文/尾部/模型信息全部保留。

结果新增字段`research_group_id`、`business_tags`、`industry_tags`、`taxonomy_version`、`peer_context`；兼容旧版本缺字段显示“未接入”，不得因此清空原预测。数据契约参见contracts/dashboard.schema.json。请求网关仍为原单一POST /jobs入口；不要仅为存储新建第二条计算链。客户端不能指定有利同行以操纵预测。

同批次缓存key/预测manifest加入taxonomy_version与peer-membership版本；旧任务不得覆盖新分类/模型结果。临时结果到达时刷新筛选选项；只读预览仍明确接口未部署。
